지난 시간에는 HTTP 메서드라는 '동사'를 배웠다면, 이번 4단계는 그 동사에 목적어를 더하는 과정인 '데이터 전송'에 대해 심도 있게 다뤄보겠습니다.



**[ 핵심 목표 ]**

---

이번 단계에서는 `requests`에서 데이터를 서버로 전달하는 대표적인 세 가지 방법을 배웁니다.

```text
params=  → URL 뒤에 붙는 쿼리 파라미터 전달
data=    → 폼 데이터 전달
json=    → JSON 데이터 전달
```

이 세 가지를 제대로 구분해야 API 문서를 읽을 때 헷갈리지 않습니다.

특히 실무에서는 API 문서에 다음과 같은 표현이 자주 나옵니다.

```text
Query Parameters
Request Body
Form Data
JSON Body
```

이 표현들이 각각 `params`, `data`, `json` 중 무엇과 연결되는지 이해하는 것이 이번 단계의 핵심입니다.

---



**[ 데이터를 전달하는 방식이 왜 나뉘는가? ]**

---

우리가 서버에 데이터를 보낼 때는 크게 두 가지 공간을 이용합니다.
클라이언트가 서버에 데이터를 보내는 방법은 **어디에 담느냐**에 따라 나뉩니다.

- **URL 뒤 (Query String):** 
  - 검색 조건, 필터, 페이지 번호처럼 "조회 조건"을 전달할 때
  - `?key=value` 형태로 주소창에 데이터가 노출됩니다. 주로 검색, 필터링, 페이지 번호 이동에 사용됩니다.
- **요청 본문 (Request Body):** 
  - 회원가입 정보, 게시글 내용처럼 "실제 데이터"를 전달할 때
  - 주소창에는 보이지 않으며, 데이터 용량이 크거나 보안이 필요한 정보(비밀번호, 게시글 본문 등)를 보낼 때 사용합니다.

requests 라이브러리는 이 두 가지 상황에 대응해 `params=`, `data=`, `json=` 세 가지 파라미터를 제공합니다. 이 셋의 차이를 정확히 이해하는 것이 4단계의 전부입니다.

---





# 1. 쿼리 파라미터란 무엇인가

쿼리 파라미터는 URL 뒤에 붙어서 서버에 추가 정보를 전달하는 값입니다.

예를 들어 아래 URL을 보겠습니다.

```text
https://example.com/search?keyword=python&page=1
```

여기서 `?` 뒤에 붙은 부분이 쿼리 스트링입니다.

```text
keyword=python&page=1
```

구조를 나누면 다음과 같습니다.

```text
기본 URL: https://example.com/search

쿼리 스트링:
keyword=python
page=1
```

즉, 서버에게 이렇게 말하는 것과 비슷합니다.

```text
검색어는 python이고,
페이지 번호는 1번입니다.
```

쿼리 파라미터는 보통 `GET` 요청에서 많이 사용합니다.

```text
검색
필터링
정렬
페이지네이션
카테고리 선택
날짜 범위 조회
```

예를 들어 쇼핑몰 API라면 이런 식으로 사용될 수 있습니다.

```text
/products?category=keyboard&page=2&sort=price
```

의미는 다음과 같습니다.

```text
keyboard 카테고리의 상품을 조회하고,
2페이지를 가져오고,
가격순으로 정렬해줘.
```

# 2. params / data / json

## 2.1. params 사용하기



### 1) params - 개념

`params=`는 URL 뒤에 붙는 쿼리 파라미터를 전달할 때 사용합니다.
`params=` 인자를 사용하면 딕셔너리 형태의 데이터를 자동으로 URL 끝에 `?key=value&key2=value2` 형태로 붙여줍니다.

* **장점:** 직접 URL에 `?key=value&key=value`를 이어붙이지 않아도 되므로 실수를 방지하고, 코드가 깔끔해집니다.

```python
requests.get(url, params={...})
```

직접 URL에 `?keyword=python&page=1`처럼 붙일 수도 있지만, 실무에서는 보통 `params`를 사용합니다.

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={"keyword": "python", "page": 1}
)

print(r.url)
print(r.text)
```

실행하면 최종 URL은 대략 다음과 비슷하게 만들어집니다.

```text
https://httpbin.org/get?keyword=python&page=1
```

즉, 아래 두 방식은 결과적으로 비슷합니다.

```python
requests.get("https://httpbin.org/get?keyword=python&page=1")
requests.get(
    "https://httpbin.org/get",
    params={"keyword": "python", "page": 1}
)
```

하지만 실무에서는 두 번째 방식이 더 좋습니다.



**[ Query String  ]**

웹 브라우저 주소창을 보면 이런 URL을 자주 접합니다.

```
https://www.google.com/search?q=python&page=1
```

여기서 `?` 뒤에 오는 부분이 **쿼리 스트링(Query String)** 입니다.

```
?q=python&page=1
 │  └──────────── 값 (value)
 └─ 키 (key)
    └──── & 로 여러 개 연결
```

구조를 정리하면 다음과 같습니다.

| 구성 요소   | 역할                               |
| ----------- | ---------------------------------- |
| `?`         | 쿼리 스트링의 시작을 알리는 구분자 |
| `key=value` | 실제 전달할 데이터                 |
| `&`         | 여러 파라미터를 연결하는 구분자    |

쿼리 스트링은 URL의 일부이므로 **누구나 주소창에서 볼 수 있습니다.** 
따라서 비밀번호나 민감한 정보를 담으면 안 됩니다.







### 2) params - 사용시기 & 용도

- 검색어, 페이지 번호, 정렬 조건, 필터 등 **조회 조건**을 전달할 때
- 서버 상태를 변경하지 않는 **GET 요청**에 데이터를 첨부할 때

---

`params`를 쓰면 코드가 더 안전하고 읽기 쉬워집니다.

```python
params = {
    "keyword": "python",
    "page": 1,
    "sort": "latest"
}

r = requests.get("https://httpbin.org/get", params=params)
```



**장점**

```text
URL을 직접 조립하지 않아도 된다
파라미터가 많아져도 관리하기 쉽다
한글, 공백, 특수문자 처리가 더 안전하다
코드 가독성이 좋아진다
```

예를 들어 검색어에 공백이 들어간다고 해보겠습니다.

```python
params = {
    "keyword": "python requests",
    "page": 1
}
```

`requests`는 이 값을 URL에 맞게 자동으로 인코딩해줍니다.

최종 URL은 이런 식으로 변환될 수 있습니다.

```text
https://httpbin.org/get?keyword=python+requests&page=1
```

직접 문자열로 붙이면 이런 인코딩 처리를 실수할 수 있기 때문에 `params`를 쓰는 습관이 좋습니다.



---



**[ params는 주로 GET 요청에서 사용한다 ]**

`params`는 보통 `GET` 요청과 함께 사용합니다.

```python
import requests

url = "https://httpbin.org/get"

params = {
    "keyword": "python",
    "page": 1
}

r = requests.get(url, params=params)

print(r.status_code)
print(r.url)		# https://httpbin.org/get?keyword=python&page=1
print(r.text)
```

흐름은 다음과 같습니다.

```text
1. 기본 URL 준비
2. params 딕셔너리 준비
3. requests.get()에 params 전달
4. requests가 URL 뒤에 쿼리 스트링 생성
5. 서버가 조건에 맞는 응답 반환
```

---

딕셔너리로 넘긴 데이터가 자동으로 URL에 인코딩되어 붙는 것을 확인할 수 있습니다.

> `r.url`을 출력해서 실제로 어떤 URL이 만들어졌는지 반드시 눈으로 확인하세요. URL이 의도한 대로 구성됐는지 검증하는 것이 디버깅의 기본입니다.







## 2.2. data 사용하기

### 1) data - 개념

`data=`는 서버에 **폼 데이터**를 보낼 때 사용합니다.

`data=`는 HTML `<form>` 태그로 데이터를 전송하는 방식과 동일한 형식입니다.
데이터가 URL이 아닌 **요청 본문(body)** 에 담기며, Content-Type이 자동으로 `application/x-www-form-urlencoded`로 설정됩니다.

```python
requests.post(url, data={...})
```

폼 데이터는 HTML의 `<form>`을 통해 전송되는 데이터와 비슷한 형식입니다.
예를 들어 웹사이트 로그인 폼을 생각해보겠습니다.

```text
아이디 입력
비밀번호 입력
로그인 버튼 클릭
```

이때 서버로 전송되는 데이터가 폼 데이터일 수 있습니다.

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    data={
        "username": "seo",
        "password": "1234"
    }
)

print(r.status_code)
print(r.text)
```

------







### 2) data - 사용시기 & 용도

`data`는 보통 다음 상황에서 사용합니다.

- 웹 사이트의 로그인 폼, 회원가입 폼처럼 **전통적인 웹 폼 제출** 방식을 흉내낼 때
- 상대 서버가 **폼 데이터 형식**을 요구할 때 (주로 레거시 시스템이나 웹 스크래핑)

```text
HTML form 전송
로그인 폼 제출
검색 폼 제출
간단한 POST 요청
application/x-www-form-urlencoded 형식 전송
```

예를 들어 어떤 사이트의 로그인 요청이 폼 데이터 방식이라면 다음처럼 보낼 수 있습니다.

```python
import requests

login_url = "https://example.com/login"

payload = {
    "username": "seo",
    "password": "1234"
}

r = requests.post(login_url, data=payload)

print(r.status_code)
print(r.text)
```

**[주의!]** 다만 실제 로그인 요청은 쿠키, 세션, CSRF 토큰, 헤더 등이 필요할 수 있기 때문에 단순히 `data`만 보낸다고 항상 로그인되는 것은 아닙니다.







### 3) data - 보내는 형식

`data`에 딕셔너리를 넣으면 보통 폼 데이터 형식으로 전송됩니다.

예를 들어:

```python
data = {
    "name": "seo",
    "age": 20
}
```

이 값은 내부적으로 대략 이런 느낌으로 전송됩니다.

```text
name=seo&age=20
```

즉, <u>URL 뒤에 붙는 것은 아니지만, 요청 본문 안에 폼 데이터 형태</u>로 들어갑니다.

```text
POST 요청
  URL: https://httpbin.org/post
  Body: name=seo&age=20
```

------

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    data={"username": "seo", "password": "1234"}
)

print(r.status_code)
print(r.text)
```

```json
{
  "form": {
    "password": "1234",
    "username": "seo"
  }
}
```

## 2.3. json 사용하기

### 1) json - 개념

`json=`은 딕셔너리를 JSON 형식의 문자열 데이터로 직렬화해서 요청 본문에 담아 보냅니다.
 Content-Type이 자동으로 `application/json`으로 설정됩니다.

```python
requests.post(url, json={...})
```

요즘 REST API나 백엔드 API에서는 `json=`을 많이 사용합니다.

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    json={
        "title": "hello",
        "content": "world"
    }
)

print(r.status_code)
print(r.text)
```

이 코드는 서버에 다음과 같은 JSON 데이터를 보내는 것과 비슷합니다.
응답 본문에서 보낸 데이터가 `"json"` 키 아래에 담겨있는 것을 확인할 수 있습니다.

```json
{
  "json": {
    "title": "hello"      
    "content": "world",
  }
}
```

> `data=`와 `json=`의 차이는 겉으로는 비슷해 보이지만, 서버 입장에서는 전혀 다른 형식입니다. API 문서에서 `Content-Type: application/json`을 요구한다면 반드시 `json=`을 써야 합니다.

------





### 2) json - 사용시기 & 용도

`json=`은 보통 API 서버와 통신할 때 많이 사용합니다.

- 현대적인 **REST API**와 통신할 때 (대부분의 외부 API가 여기 해당)
- 서버가 JSON 형식의 요청 본문을 요구할 때
- 실무에서 POST/PUT/PATCH 요청에 데이터를 담을 때 가장 많이 사용하는 방식

```text
REST API 요청
백엔드 서버에 데이터 생성 요청
게시글 작성 API
댓글 작성 API
사용자 정보 수정 API
외부 서비스 API 호출
```

예를 들어 게시글 작성 API라면 다음처럼 보낼 수 있습니다.

```python
import requests

url = "https://example.com/posts"
payload = {
    "title": "requests 학습",
    "content": "params, data, json 차이 정리"
}

r = requests.post(url, json=payload)

print(r.status_code)
print(r.text)
```

서버 입장에서는 다음과 같은 JSON 데이터를 받게 됩니다.

```json
{
  "title": "requests 학습",
  "content": "params, data, json 차이 정리"
}
```

------





### 3) json - 장점

`json=`을 사용하면 `requests`가 자동으로 두 가지 일을 해줍니다.

```text
Python 딕셔너리를 JSON 문자열로 변환한다
Content-Type을 application/json으로 설정한다
```

즉, 아래처럼 직접 처리하지 않아도 됩니다.

```python
import json
import requests

headers = {"Content-Type": "application/json"}
data = json.dumps({"title": "hello", "content": "world"})

r = requests.post(
    "https://httpbin.org/post",
    headers=headers,
    data=data
)
```

대부분의 경우에는 이렇게 간단히 쓰면 됩니다.

```python
r = requests.post(
    "https://httpbin.org/post",
    json={"title": "hello", "content": "world"}
)
```

그래서 API 통신에서는 `json=`을 우선적으로 생각하면 됩니다.

------





## [ params, data, json의 차이 ]

세 가지를 한 번에 정리하면 다음과 같습니다.

| 구분                 | `params=`                                     | `data=`                                                      | `json=`                                                      |
| -------------------- | --------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 데이터 위치          | URL 뒤 (쿼리 스트링)                          | 요청 본문 (body)                                             | 요청 본문 (body)                                             |
| Content-Type         | 없음 (URL의 일부)                             | `application/x-www-form-urlencoded`                          | `application/json`                                           |
| 주로 사용하는 메서드 | GET                                           | POST                                                         | POST / PUT / PATCH                                           |
| 주 사용 목적         | URL 파라미터 (전송) - 조회 조건, 필터, 페이지 | 폼 데이터 (전송) - 웹 폼 제출, 레거시 API                    | JSON 데이터 (전송) - REST API 통신                           |
| 가시성               | URL에 노출됨                                  | 본문에 숨겨짐                                                | 본문에 숨겨짐                                                |
| 설명                 | URL 에 뒤에 붙는 조건 파리미터로 사용된다     | 전통적인 HTML `<form>` 태그를 통해 전송할 때 사용하는 방식입니다. | **최신 REST API의 표준**입니다. 파이썬 딕셔너리를 자동으로 JSON 문자열로 변환하여 전송합니다. |

------

조금 더 쉽게 보면 다음과 같습니다.

**params**
→ URL 뒤에 붙여서 조건을 전달한다
→ 검색, 필터, 페이지 번호에 자주 사용

**data**
→ 폼 데이터로 본문에 담아 보낸다
→ 로그인 폼, HTML form 제출에 자주 사용
→ <u>Content-Type(헤더)</u>: `application/x-www-form-urlencoded`

**json**
→ JSON 형식으로 본문에 담아 보낸다
→ REST API, 백엔드 API 통신에 자주 사용
→ <u>Content-Type(헤더)</u>: `application/json

---

POST 메서드로 데이터를 보낼 때는 본문(Body)에 담기는 데이터의 형식을 지정해야 합니다. 이 구분을 명확히 하는 것이 가장 중요합니다.

```python

requests.post(
```

```python
requests.post(
```

# 3. API 문서 읽는 법

**API 문서에서 query parameter와 request body 구분하기**

이 단계에서 가장 중요한 실무 능력은 API 문서를 읽을 때 다음을 구분하는 것입니다.
문서에 적힌 용어에 따라 `requests`의 인자를 결정하세요.

- **"Query Parameters" 또는 "URL Parameters"라고 적혀 있다면?** ➔ `params=` 사용
- **"Request Body" 또는 "Payload"가 JSON 형식이라면?** ➔ `json=` 사용
- **"Form Data"라고 명시되어 있다면?** ➔ `data=` 사용

```text
Query Parameter인가?
Request Body인가?
```

------



## 3.1. Query Parameter

* **<u>Query Parameter라고 되어 있으면 params 사용</u>**

API 문서에 이런 식으로 적혀 있다고 해보겠습니다.

```text
GET /books/search

Query Parameters:
keyword: 검색어
page: 페이지 번호
sort: 정렬 기준
```

그러면 Python 코드는 보통 이렇게 작성합니다.

```python
import requests

url = "https://example.com/books/search"

params = {
    "keyword": "python",
    "page": 1,
    "sort": "sales"
}

r = requests.get(url, params=params)

print(r.url)
print(r.status_code)
print(r.text)
```

해석하면 다음과 같습니다.

```text
GET 요청이다
검색 조건은 Query Parameters다
그러므로 params=를 사용한다
```

------





## 3.2. Request Body

* **<u>Request Body라고 되어 있으면 data 또는 json 사용</u>**

API 문서에 이런 식으로 적혀 있다고 해보겠습니다.

```text
POST /posts

Request Body:
{
  "title": "string",
  "content": "string"
}
```

이 경우는 URL 뒤에 붙이는 값이 아니라 요청 본문에 담아 보내는 값입니다.

요즘 API 문서에서 JSON 형태로 Request Body를 보여준다면 보통 `json=`을 사용하면 됩니다.

```python
import requests

url = "https://example.com/posts"

body = {
    "title": "hello",
    "content": "world"
}

r = requests.post(url, json=body)

print(r.status_code)
print(r.text)
```

해석하면 다음과 같습니다.

```text
POST 요청이다
데이터는 Request Body에 들어간다
본문 형식이 JSON이다
그러므로 json=을 사용한다
```

------





## 3.3. Form Data

* **<u>Form Data라고 되어 있으면 data 사용</u>**

API 문서에 이런 식으로 적혀 있다면:

```text
POST /login

Form Data:
username
password
```

보통 `data=`를 사용합니다.

```python
import requests

url = "https://example.com/login"

form_data = {
    "username": "seo",
    "password": "1234"
}

r = requests.post(url, data=form_data)

print(r.status_code)
print(r.text)
```

해석하면 다음과 같습니다.

```text
POST 요청이다
데이터 형식은 Form Data다
그러므로 data=를 사용한다
```

------

## 4.4 params와 json을 함께 쓰는 예제

실무에서는 `params`와 `json`을 함께 쓰는 경우도 있습니다.

예를 들어:

```text
POST /posts?notify=true
```

그리고 본문에는 게시글 데이터를 보낸다고 해보겠습니다.

```python
import requests

url = "https://httpbin.org/post"

params = {
    "notify": "true"
}

body = {
    "title": "hello",
    "content": "world"
}

r = requests.post(
    url,
    params=params,
    json=body
)

print("최종 URL:", r.url)
print("상태 코드:", r.status_code)
print("응답 본문:", r.text)
```

이 경우 구조는 다음과 같습니다.

```text
URL 쪽 조건:
notify=true

본문 데이터:
{
  "title": "hello",
  "content": "world"
}
```

즉, `params`와 `json`은 역할이 다릅니다.

```text
params → URL에 붙는 조건
json   → 요청 본문에 들어가는 데이터
```

------



### 세 가지 한 파일에서 비교

```python
import requests

# 1. params= — URL에 조회 조건 붙이기
r1 = requests.get(
    "https://httpbin.org/get",
    params={"keyword": "python", "page": 1}
)
print("[GET + params] URL:", r1.url)

# 2. data= — 폼 데이터로 전송
r2 = requests.post(
    "https://httpbin.org/post",
    data={"username": "seo", "password": "1234"}
)
print("[POST + data] status:", r2.status_code)

# 3. json= — JSON으로 전송 (REST API 방식)
r3 = requests.post(
    "https://httpbin.org/post",
    json={"title": "hello", "content": "world"}
)
print("[POST + json] status:", r3.status_code)
```

세 가지를 나란히 실행해보면 `r1.url`에는 파라미터가 붙어있고, `r2`와 `r3`의 응답 본문을 비교하면 `"form"` 키와 `"json"` 키로 담기는 위치가 다른 것을 직접 확인할 수 있습니다.

------

**정리하면**, 데이터를 어디에 담느냐가 핵심입니다. URL 뒤에 붙는 조회 조건은 `params=`, 폼 형식의 전송은 `data=`, REST API와 통신할 때는 `json=`을 사용한다는 원칙을 기억하세요. <u>실무에서는 `params=`와 `json=` 조합을 가장 자주 사용하게 됩니다.</u>

# 5. 자주 하는 실수

## 5.1 GET 요청인데 data를 사용하는 경우

초보자가 가끔 이렇게 작성합니다.

```python
requests.get(
    "https://httpbin.org/get",
    data={"keyword": "python"}
)
```

하지만 `GET` 요청에서 검색 조건을 전달하려면 보통 `params`를 사용합니다.

```python
requests.get(
    "https://httpbin.org/get",
    params={"keyword": "python"}
)
```

정리하면 다음과 같습니다.

```text
GET에서 검색 조건 전달 → params
POST에서 폼 데이터 전달 → data
POST에서 JSON 데이터 전달 → json
```

------



## 5.2. API 문서가 JSON을 요구하는데 data를 쓰는 경우

API 문서에 Request Body가 JSON이라고 되어 있는데 아래처럼 작성하면 문제가 생길 수 있습니다.

실무에서 가장 흔하게 발생하는 실수는 **API는 JSON을 원하는데 `data=`로 보내는 경우**입니다. 만약 서버가 `400 Bad Request`나 `415 Unsupported Media Type`을 반환한다면, 가장 먼저 이 부분을 의심해 보십시오. `json=`을 사용하면 `requests` 라이브러리가 헤더 설정까지 알아서 처리해주므로 훨씬 편리하고 안전합니다.

```python
requests.post(
    url,
    data={"title": "hello", "content": "world"}
)
```

이 경우 서버는 JSON을 기대하는데, 클라이언트는 폼 데이터로 보내게 됩니다.

JSON API라면 이렇게 작성하는 것이 좋습니다.

```python
requests.post(
    url,
    json={"title": "hello", "content": "world"}
)
```

```python
json_data = {
```

# [ 핵심 정리 ]

이번 단계에서 반드시 기억해야 할 내용은 다음과 같습니다.

| 옵션      | 의미              | 주 사용 상황              | 예시                     |
| --------- | ----------------- | ------------------------- | ------------------------ |
| `params=` | URL 파라미터 전송 | GET 검색, 조회, 필터링    | `?keyword=python&page=1` |
| `data=`   | 폼 데이터 전송    | 로그인 폼, HTML form 제출 | `name=seo&age=20`        |
| `json=`   | JSON 데이터 전송  | REST API, 백엔드 API 통신 | `{"title": "hello"}`     |

가장 중요한 예제는 아래 두 개입니다.

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={"keyword": "python", "page": 1}
)

print(r.url)


import requests

r = requests.post(
    "https://httpbin.org/post",
    json={"title": "hello", "content": "world"}
)

print(r.status_code)
print(r.text)
```

------



**[ 교수 관점에서 보는 핵심 개념 ]**

이 단계에서 가장 중요한 것은 `params`, `data`, `json`을 단순히 외우는 것이 아닙니다.

---

**첫째, params / data / json 의 차이를 명확히 구분하세요.**

셋 다 데이터를 보내는 수단이지만 전달 위치와 형식이 다릅니다. 잘못된 파라미터를 쓰면 서버가 데이터를 받지 못하거나 오류를 반환합니다. 이 차이를 모르면 API 연동 시 원인 불명의 오류에 시달리게 됩니다.

진짜 중요한 기준은 **데이터가 어디로 들어가는가**입니다.

```text
params는 URL에 들어간다.
data는 요청 본문에 폼 데이터로 들어간다.
json은 요청 본문에 JSON으로 들어간다.
```

---

**둘째, API 문서에서 Query Parameter와 Request Body를 구분해서 읽는 습관을 만드세요.**

모든 API 문서는 파라미터를 두 영역으로 나눠 설명합니다.

- **Query Parameters** : URL에 붙는 조건 → `params=` 사용
- **Request Body** : 본문에 담는 데이터 → `json=` 또는 `data=` 사용

API 문서를 읽을 때 이 두 영역을 구분하는 것만으로도 연동 성공률이 크게 올라갑니다.
API 문서를 읽을 때는 다음 질문을 먼저 해야 합니다.

```text
이 값은 Query Parameter인가?
이 값은 Request Body인가?
Request Body라면 Form Data인가 JSON인가?
```

이 질문에 답할 수 있으면 `requests` 코드를 안정적으로 작성할 수 있습니다.

```text
Query Parameter → params
Form Data → data
JSON Body → json
```

결국 이번 단계의 목표는 이것입니다.

```text
API 문서를 보고
어떤 데이터를
어디에
어떤 형식으로
보내야 하는지 판단하는 능력
```

이 능력이 생기면 이후에 공공 API, YouTube API, 쇼핑몰 API, 책 검색 API, 로그인 요청, 크롤링 자동화 코드를 훨씬 더 정확하게 작성할 수 있습니다.

---
