# 학습 키워드 정리

* `params=`
* ``data=`
* `json=`
* Query Parameters
* Request Body
* Form Data
* JSON Body
* `application/x-www-form-urlencoded`
* `application/json`



## 1. 주요 키워드 목록

| 키워드                              | 분류             | 중요도 | 한 줄 설명                                                   |
| ----------------------------------- | ---------------- | ------ | ------------------------------------------------------------ |
| `params=`                           | 필수 암기 키워드 | 5      | URL 뒤 쿼리 스트링에 조회 조건을 전달할 때 사용하는 requests 인자 |
| `data=`                             | 필수 암기 키워드 | 5      | 요청 본문에 폼 데이터 형식으로 데이터를 보낼 때 사용하는 requests 인자 |
| `json=`                             | 필수 암기 키워드 | 5      | 요청 본문에 JSON 형식으로 데이터를 보낼 때 사용하는 requests 인자 |
| Query Parameters                    | 필수 암기 키워드 | 5      | API 문서에서 URL에 붙는 조건 값을 의미하며 `params=`와 연결됨 |
| Request Body                        | 필수 암기 키워드 | 5      | URL이 아닌 요청 본문에 담아 보내는 데이터 영역               |
| Form Data                           | 필수 암기 키워드 | 5      | HTML form 제출 방식의 데이터 형식이며 `data=`와 연결됨       |
| JSON Body                           | 필수 암기 키워드 | 5      | JSON 형식의 요청 본문이며 `json=`과 연결됨                   |
| Query String                        | 필수 암기 키워드 | 5      | URL의 `?` 뒤에 붙는 `key=value` 형태의 데이터 문자열         |
| GET 요청                            | 필수 암기 키워드 | 4      | 서버 상태를 바꾸지 않고 조회 조건을 전달할 때 주로 사용하는 HTTP 요청 |
| POST 요청                           | 필수 암기 키워드 | 4      | 요청 본문에 데이터를 담아 서버로 전송할 때 주로 사용하는 HTTP 요청 |
| URL 뒤 데이터 전달                  | 일반 학습 키워드 | 4      | 검색어, 필터, 페이지 번호처럼 조회 조건을 주소에 포함하는 방식 |
| 요청 본문 데이터 전달               | 일반 학습 키워드 | 4      | 회원가입 정보나 게시글 내용처럼 실제 데이터를 body에 담아 보내는 방식 |
| `application/x-www-form-urlencoded` | 필수 암기 키워드 | 4      | `data=` 사용 시 폼 데이터 전송에 주로 사용되는 Content-Type  |
| `application/json`                  | 필수 암기 키워드 | 5      | `json=` 사용 시 JSON 데이터 전송에 사용되는 Content-Type     |
| URL 인코딩                          | 일반 학습 키워드 | 3      | 공백, 한글, 특수문자를 URL에 맞는 형식으로 변환하는 처리     |
| `r.url`                             | 일반 학습 키워드 | 4      | 실제 요청에 사용된 최종 URL을 확인하는 디버깅용 속성         |
| `r.status_code`                     | 일반 학습 키워드 | 3      | 서버 응답의 상태 코드를 확인하는 속성                        |
| `r.text`                            | 일반 학습 키워드 | 3      | 서버 응답 본문을 문자열로 확인하는 속성                      |
| Payload                             | 일반 학습 키워드 | 3      | 서버로 보내는 요청 데이터 전체를 가리키는 표현               |
| REST API                            | 필수 암기 키워드 | 4      | JSON 형식의 요청 본문을 자주 사용하는 현대적인 API 방식      |
| HTML form                           | 일반 학습 키워드 | 4      | `data=`와 연결되는 전통적인 웹 폼 제출 구조                  |
| CSRF 토큰                           | 일반 학습 키워드 | 2      | 실제 로그인 요청에서 추가로 필요할 수 있는 보안 토큰         |
| 쿠키                                | 일반 학습 키워드 | 2      | 로그인 상태나 세션 유지에 사용될 수 있는 클라이언트 저장 정보 |
| 세션                                | 일반 학습 키워드 | 2      | 서버가 사용자의 로그인 상태를 유지하기 위해 사용하는 정보    |
| 헤더                                | 일반 학습 키워드 | 3      | Content-Type 등 요청의 부가 정보를 담는 영역                 |
| `400 Bad Request`                   | 일반 학습 키워드 | 3      | 잘못된 요청 형식 때문에 발생할 수 있는 오류 상태 코드        |
| `415 Unsupported Media Type`        | 일반 학습 키워드 | 3      | 서버가 요청 Content-Type을 지원하지 않을 때 발생할 수 있는 오류 |
| `params` vs `data`                  | 비교 키워드      | 5      | URL 쿼리 조건 전달과 본문 폼 데이터 전달의 차이를 구분해야 함 |
| `data` vs `json`                    | 비교 키워드      | 5      | 같은 요청 본문이라도 폼 형식과 JSON 형식의 차이를 구분해야 함 |
| Query Parameter vs Request Body     | 비교 키워드      | 5      | URL에 붙는 조건인지 본문에 담는 데이터인지 구분해야 함       |
| Form Data vs JSON Body              | 비교 키워드      | 5      | API 문서에서 요구하는 본문 형식에 따라 `data=`와 `json=`을 선택해야 함 |
| GET vs POST                         | 비교 키워드      | 4      | 조회 중심 요청과 데이터 전송 중심 요청의 차이를 구분해야 함  |
| URL 노출 vs 본문 숨김               | 비교 키워드      | 4      | 쿼리 파라미터는 주소창에 보이고 본문 데이터는 URL에 보이지 않음 |
| 직접 URL 조립 vs `params` 사용      | 비교 키워드      | 4      | 문자열로 URL을 직접 만드는 방식보다 `params` 사용이 안전하고 관리하기 쉬움 |
| `params`와 `json` 함께 사용         | 일반 학습 키워드 | 4      | URL 조건은 `params`, 본문 데이터는 `json`으로 동시에 보낼 수 있음 |
