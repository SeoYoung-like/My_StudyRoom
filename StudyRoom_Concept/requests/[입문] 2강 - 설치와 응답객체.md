# 2단계. 설치와 첫 요청 보내기

**[ 핵심 목표 ]**

이번 단계의 목표는 **Python에서 외부 웹 서버에 요청을 보내고, 서버가 돌려준 응답을 확인하는 기본 흐름**을 익히는 것입니다.

즉, `requests` 라이브러리를 사용해서 다음 과정을 이해해야 합니다.

```text
Python 코드
  → 웹 서버에 요청 보내기
  → 서버가 응답 반환
  → 응답 상태 코드 / 본문 / 헤더 확인
```

이 단계는 웹 크롤링, API 사용, 자동화 프로그램, 데이터 수집 프로그램을 만들 때 가장 기본이 되는 출발점입니다.

------





# 1. requests란 무엇인가

`requests`는 Python에서 **HTTP 요청을 쉽게 보낼 수 있게 해주는 라이브러리**입니다.

Python은 기본적으로 HTTP 요청을 보낼 수 있는 `urllib` 모듈을 내장하고 있습니다. 파이썬의 표준 라이브러리에도 `urllib`가 존재하지만, 실무에서는 훨씬 직관적이고 사용하기 편리한 `requests`를 주로 사용합니다. 그러나 코드가 복잡하고 사용하기 불편하다는 단점이 있습니다.

`requests`는 이를 보완한 **서드파티 라이브러리**로, 한 줄로 HTTP 요청을 보낼 수 있을 만큼 직관적인 인터페이스를 제공합니다. 실무에서 가장 많이 사용하는 HTTP 클라이언트 라이브러리이며, 사실상 Python 생태계의 표준입니다.

---

웹사이트나 API 서버와 통신할 때 보통 다음과 같은 요청을 보냅니다.

```text
데이터 주세요
로그인 요청할게요
검색 결과 주세요
상품 목록 주세요
유튜브 영상 정보 주세요
책 검색 결과 주세요
```

이런 요청을 Python 코드로 보내게 해주는 대표적인 라이브러리가 `requests`입니다.

예를 들어 브라우저에서 아래 주소에 접속하면:

```text
https://httpbin.org/get
```

브라우저가 서버에 요청을 보내고, 서버는 결과를 보여줍니다.

`requests`를 사용하면 이 과정을 Python 코드로 할 수 있습니다.

------







# 2. requests 설치하기

먼저 터미널 또는 명령 프롬프트에서 아래 명령어를 입력합니다.

```bash
pip install requests
```

이미 설치되어 있다면 보통 이런 메시지가 나올 수 있습니다.

```text
Requirement already satisfied: requests
```

이건 이미 설치되어 있다는 뜻이므로 문제가 아닙니다.

설치 후 Python 코드에서 아래처럼 불러옵니다.

```python
import requests
```

여기서 `import requests`는 “requests 라이브러리를 이 코드에서 사용하겠다”는 의미입니다.

> 설치 후 `pip show requests` 명령으로 버전과 설치 경로를 확인하는 습관을 들이면 좋습니다.

# 3. 첫 번째 GET 요청 보내기

가장 기본적인 요청은 `GET` 요청입니다.

`requests.get(url)`은 지정한 URL에 **GET 요청**을 보내는 함수입니다.
 GET 요청은 서버로부터 **데이터를 가져올 때** 사용하는 가장 기본적인 HTTP 메서드입니다.

```python
response = requests.get("https://httpbin.org/get")
```

- 함수를 호출하면 요청이 즉시 서버로 전송됩니다.
- 서버의 응답이 돌아오면 그 결과가 `response` 변수(응답 객체)에 저장됩니다.
- **<u>`httpbin.org`는 HTTP 요청을 테스트할 수 있도록 만들어진 공개 테스트 서버입니다. 학습 단계에서 적극 활용하세요.</u>**

예를 들어 웹페이지를 열거나, API에서 정보를 가져오거나, 검색 결과를 가져올 때 많이 사용합니다.

```python
import requests

response = requests.get("https://httpbin.org/get")
```

이 코드의 의미는 다음과 같습니다.

```text
https://httpbin.org/get 주소로 GET 요청을 보낸다.
서버가 응답한 결과를 response 변수에 저장한다.
```

여기서 중요한 점은 `requests.get()`의 결과가 단순한 문자열이 아니라는 것입니다.

결과는 **Response 객체**입니다.





# 4. 응답 객체 Response 이해하기

`requests.get()`이 반환하는 것은 단순한 문자열이 아닙니다.
`requests.get()`을 실행하면 서버의 응답이 `response`라는 객체에 담깁니다.

**Response 객체**라는 복합적인 데이터 구조로, 서버 응답의 모든 정보를 담고 있습니다.

```python
response = requests.get("https://httpbin.org/get")
```

이 `response` 안에는 여러 정보가 들어 있습니다.

대표적으로 다음과 같은 정보가 있습니다.

```text
상태 코드
본문 내용
응답 헤더
최종 요청 URL
인코딩 정보
쿠키
요청에 사용된 정보
```

이번 단계에서는 가장 기본적인 네 가지를 먼저 보면 됩니다.

```python
response.status_code
response.text
response.headers
response.url
```

- **response.status_code (★):** 서버의 응답 상태를 나타내는 숫자입니다. (예: 200은 성공, 404는 페이지 없음)
- **response.text (★):** 서버가 보낸 본문(Body) 내용을 유니코드 텍스트 형태로 반환합니다. 주로 HTML 코드나 JSON 문자열이 담깁니다.
- **response.headers:** 서버가 응답과 함께 보낸 메타 데이터(콘텐츠 타입, 서버 정보, 시간 등)를 딕셔너리 형태로 보여줍니다.
- **response.url:** 최종적으로 요청이 도달한 URL입니다. (리다이렉트가 발생했을 경우 원래 요청한 URL과 다를 수 있습니다.)





## 4.1. response.status_code  ★ (핵심)

**[ status_code란? ]**

`status_code`는 서버가 요청을 어떻게 처리했는지 알려주는 숫자입니다.

서버가 요청을 어떻게 처리했는지를 나타내는 **3자리 숫자 코드**입니다.

```python
print(response.status_code)  # 예: 200
```

예를 들어 결과가 `200`이면 요청이 정상적으로 처리되었다는 뜻입니다.

대표적인 상태 코드는 다음과 같습니다.

| 상태 코드 | 의미                                                     |
| --------- | -------------------------------------------------------- |
| 200       | 정상 성공                                                |
| 301, 302  | 다른 주소로 이동됨                                       |
| 400       | 잘못된 요청                                              |
| 401       | 인증 필요                                                |
| 403       | 접근 금지 ( 접근 권한 없음 )                             |
| 404       | 페이지 또는 데이터 없음 ( 요청한 리소스를 찾을 수 없음 ) |
| 500       | 서버 내부 오류                                           |

가장 먼저 익혀야 할 습관은 이것입니다.

```python
response = requests.get(url)

print(response.status_code)
```

왜냐하면 서버 요청이 실패했는데도 바로 `response.text`만 보면, 왜 이상한 결과가 나왔는지 모를 수 있기 때문입니다.

실무에서는 보통 이렇게 확인합니다.

```python
if response.status_code == 200:
    print("요청 성공")
else:
    print("요청 실패:", response.status_code)
```

> 실무에서는 반드시 status_code를 먼저 확인한 후 본문을 처리합니다. 응답이 왔다고 해서 항상 성공한 것이 아닙니다.

------





## 4.2. response.text  ★ (핵심)

**[ response.text란? ]**

서버가 <u>응답한</u> **본문(body) 내용을 문자열로** 반환합니다.
( `response.text`는 서버가 보내준 **본문 내용**입니다. )

- <u>HTML 페이지, JSON 문자열, 일반 텍스트 등 서버가 보내는 내용</u>이 그대로 들어있습니다.
- 내부적으로 <u>인코딩을 자동으로 감지해 문자열로 변환</u>해 줍니다.

```python
print(response.text)  # 응답 본문 전체 출력
```

웹페이지라면 HTML이 들어 있을 수 있고, API라면 JSON 문자열이 들어 있을 수 있습니다.

예를 들어 `https://httpbin.org/get`에 요청을 보내면 대략 이런 형태의 응답이 나옵니다.

```json
{
  "args": {},
  "headers": {
    "Accept": "*/*",
    "Host": "httpbin.org"
  },
  "origin": "사용자 IP",
  "url": "https://httpbin.org/get"
}
```

여기서 중요한 점은 `response.text`는 기본적으로 **문자열**이라는 것입니다.

즉, 화면에 출력해서 응답이 어떤 구조인지 확인할 때 좋습니다.

```python
print(type(response.text))
```

결과는 보통 다음과 같습니다.

```text
<class 'str'>
```

나중에 API 응답이 JSON 형식이라면 `response.json()`을 사용해서 Python 딕셔너리처럼 다룰 수 있습니다.

하지만 이번 단계에서는 먼저 `text`로 본문을 확인하는 습관을 익히는 것이 중요합니다.





## 4.3. response.headers

`response.headers`는 서버가 응답과 함께 보내는 부가 정보입니다.
서버가 응답과 함께 보낸 **헤더 정보**를 딕셔너리 형태로 반환합니다.

```python
print(response.headers)
# {'Content-Type': 'application/json', 'Date': '...', ...}
```

- 응답 데이터의 타입(`Content-Type`), 인코딩, 서버 종류 등의 메타 정보가 포함됩니다.
- 특정 헤더 값만 꺼낼 때는 `response.headers["Content-Type"]` 처럼 사용합니다.

---

헤더에는 이런 정보가 들어 있을 수 있습니다.

```text
응답 데이터의 형식
서버 정보
캐시 정책
쿠키 정보
압축 방식
응답 시간 관련 정보
```

예를 들어 이런 값이 있을 수 있습니다.

```text
Content-Type: application/json
```

이 뜻은 서버가 보내준 응답 본문이 JSON 형식이라는 의미입니다.

실무에서 `headers`는 다음과 같은 상황에서 자주 확인합니다.

```text
응답이 HTML인지 JSON인지 확인할 때
로그인이 필요한 요청인지 확인할 때
쿠키가 설정되었는지 확인할 때
서버가 어떤 형식으로 데이터를 주는지 확인할 때
```

예시:

```python
print(response.headers["Content-Type"])
```

다만 특정 헤더가 없을 수도 있으므로 안전하게 확인하려면 `.get()`을 쓰는 것이 좋습니다.

```python
print(response.headers.get("Content-Type"))
```

------



## 4.4. response.url

`response.url`은 최종적으로 요청이 처리된 **최종 URL**을 반환 합니다.

```python
print(response.url)
# https://httpbin.org/get
```

- 리다이렉트(redirect)가 발생했을 경우, 처음 보낸 URL과 최종 URL이 다를 수 있습니다.
- 의도한 곳으로 요청이 갔는지 디버깅할 때 유용합니다.

처음 요청한 URL과 최종 URL이 항상 같은 것은 아닙니다.

예를 들어 어떤 사이트는 요청을 받으면 다른 주소로 자동 이동시킬 수 있습니다.

```text
http://example.com
→ https://example.com
```

또는 로그인 페이지로 이동할 수도 있습니다.

```text
https://example.com/my-page
→ https://example.com/login
```

이런 경우 `response.url`을 확인하면 최종적으로 어디에 도착했는지 알 수 있습니다.

실무에서는 크롤링이나 API 요청을 할 때 `response.url`을 확인하는 것이 꽤 중요합니다.





# 5. 전체 예제 코드

가장 기본적인 예제입니다.

```python
import requests

response = requests.get("https://httpbin.org/get")

print(response.status_code)
print(response.text)
```

조금 더 실무적으로 확인하면 이렇게 작성할 수 있습니다.

```python
import requests

url = "https://httpbin.org/get"

response = requests.get(url)

print("상태 코드:", response.status_code)
print("최종 URL:", response.url)
print("응답 헤더:", response.headers)
print("응답 본문:", response.text)
```

조금 더 안전하게 작성하면 다음과 같습니다.

```python
import requests

url = "https://httpbin.org/get"

response = requests.get(url)

if response.status_code == 200:
    print("요청 성공")
    print(response.text)
else:
    print("요청 실패")
    print("상태 코드:", response.status_code)
```



## [ 실습 예제 및 해설 ]

```python
import requests

# 1. GET 요청 보내기
response = requests.get("https://httpbin.org/get")

# 2. 상태 코드 확인 (가장 먼저 확인할 것)
print(response.status_code)   # 200

# 3. 본문 내용 확인
print(response.text)          # JSON 형태의 문자열 출력

# 4. 추가 정보 확인
print(response.headers)       # 응답 헤더
print(response.url)           # 최종 요청 URL
```

**실행 결과 흐름 설명**

```
200                          ← 요청이 정상 처리됨
{
  "args": {},
  "headers": { ... },
  "origin": "x.x.x.x",
  "url": "https://httpbin.org/get"
}                            ← 서버가 받은 요청 정보를 그대로 돌려줌
```

> `httpbin.org`는 내가 보낸 요청 정보를 그대로 응답으로 돌려주기 때문에, 내 요청이 어떻게 전달됐는지 확인하는 데 최적의 테스트 도구입니다.

------

**정리하면**, 이 단계는 HTTP 통신의 기본 사이클인 **요청(Request) → 응답(Response) → 확인** 흐름을 손에 익히는 단계입니다. 이 흐름이 자연스러워지면 이후 POST 요청, 인증, 에러 처리 등 모든 심화 내용이 쉽게 이해됩니다.





# 6. 이 단계에서 꼭 익혀야 할 습관

## 6.1. get으로 데이터 받아오기

가장 먼저 익혀야 할 코드는 이것입니다.

```python
response = requests.get("https://httpbin.org/get")
```

이 코드를 보면 바로 이런 구조를 떠올릴 수 있어야 합니다.

```text
requests.get()
→ 서버에 GET 요청
→ 응답을 response에 저장
```



## 6.2. status_code 확인하기

요청을 보냈으면 가장 먼저 상태 코드를 확인하는 습관을 들여야 합니다.

```python
print(response.status_code)
```

특히 자동화나 크롤링 코드를 만들 때는 상태 코드를 확인하지 않으면 오류 원인을 찾기 어렵습니다.

좋은 습관:

```python
if response.status_code == 200:
    print("성공")
else:
    print("실패:", response.status_code)
```



## 6.3. text로 본문 확인하기

처음 요청을 보냈을 때는 서버가 어떤 데이터를 주는지 먼저 확인해야 합니다.

```python
print(response.text)
```

이걸 통해 다음을 확인할 수 있습니다.

```text
HTML이 오는지
JSON이 오는지
에러 메시지가 오는지
로그인 페이지가 오는지
차단 메시지가 오는지
```

특히 크롤링할 때는 내가 원하는 데이터가 `response.text` 안에 실제로 들어 있는지 확인하는 것이 매우 중요합니다.

------



# 7. 핵심 정리

이번 단계에서 가장 중요한 코드는 아래입니다.

```python
import requests

response = requests.get("https://httpbin.org/get")

print(response.status_code)
print(response.text)
```

이 코드를 완전히 이해하면 `requests`의 가장 기본적인 흐름을 익힌 것입니다.

정리하면 다음과 같습니다.

| 코드                   | 의미                         |
| ---------------------- | ---------------------------- |
| `import requests`      | requests 라이브러리 불러오기 |
| `requests.get(url)`    | 해당 URL로 GET 요청 보내기   |
| `response.status_code` | 요청 성공 여부 확인          |
| `response.text`        | 응답 본문 확인               |
| `response.headers`     | 응답 헤더 확인               |
| `response.url`         | 최종 요청 URL 확인           |

# 8. 교수 관점에서 보는 학습 포인트

이 단계에서는 코드를 많이 외우기보다 **요청과 응답의 흐름**을 이해하는 것이 중요합니다.

초보자는 보통 이렇게 생각합니다.

```text
requests.get()을 쓰면 데이터가 나온다
```

하지만 정확히는 이렇게 이해해야 합니다.

```text
requests.get()은 서버에 HTTP 요청을 보낸다.
서버는 Response 객체를 돌려준다.
우리는 Response 객체 안에서 상태 코드, 본문, 헤더 등을 확인한다.
```

즉, 핵심은 이것입니다.

```text
요청 Request
응답 Response
상태 코드 Status Code
본문 Body
헤더 Header
```

이 개념을 잡아야 이후에 API, 크롤링, 로그인 요청, 파일 다운로드, 자동화 프로그램을 안정적으로 만들 수 있습니다.
